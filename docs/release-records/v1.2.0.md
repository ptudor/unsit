## Downloaded app and live updater

On an Apple silicon Mac running macOS 26.6.2, fresh downloads passed the release
verifier with `--require-notarized --macos`, including app/helper signatures,
signing team, Hardened Runtime, timestamps, notarization tickets, Gatekeeper,
helper self-test, a read-only DMG mount, and one complete set of string tables
for every one of the 84 bundled languages. Intel metadata, receipts, checksums,
and provenance were verified locally; its native runtime and signing checks
passed on the Intel runner above.

The arm64 installer that the real update client downloaded was mounted with its
quarantine marker, and the app copied out of it kept that marker. Gatekeeper
assessed it as `Notarized Developer ID`, its stapled ticket validated, it
reports version 1.2.0 with 84 language folders, it launched and stayed running
in French, and its bundled helper reported `unsit 1.2.0` and recovered a
synthetic preset archive.

The real update client passed locally for **arm64 and x86_64**: stable release
discovery, manifest validation, installer size and SHA-256, quarantined
download, and no newer update when already on 1.2.0. The probe supplied 0.0.0
as its starting version, as in the 1.0.0 record; a check from an installed
public 1.0.0 app through **Download Update** remains to be done by hand.

Minimum macOS 11 CLI / macOS 12 app and Swift 5.7 runtime validation remains a
separate platform gate. See [verification limits](../verification.md).

## Corrections

Before the tag, [CI run 35293476452](https://github.com/ptudor/unsit/actions/runs/35293476452)
on `c0b5f1d` failed release verification on both native runners: their Xcode
16.4 `xcstringstool` writes an English table only for keys with an explicit
source value, unlike Xcode 26, so the bundle lacked three English tables.
Commits `c88a940` and `6dc8905` made the verifier name the language and tables
and made `scripts/package.py` write the development language's tables from the
catalogs, so the bundle no longer depends on which Xcode built it.

The release run itself needed two corrections; the published assets were built,
signed, notarized, and attested once, and were never replaced:

1. The `release` job created its draft, then stopped with "Created draft could
   not be found": GitHub's releases list lagged a few seconds behind the create.
   The empty draft carrying the tag was confirmed, the failed jobs were rerun,
   and the rerun resumed that draft, uploaded and verified the artifacts,
   attested them, and published once. Commit `617aaef` makes the publisher
   wait for a new draft to appear.
2. The `live-updater` job then failed to compile its probe: the probe is built
   with `swiftc` from `AppUpdate.swift`, which now uses `Strings.swift`, and the
   workflow, runbook, and probe header listed only the one file. The commit
   recording this release adds the missing source in all three places and makes
   CI compile the probe on both native runners. The live updater check was run
   locally instead, as recorded above.
