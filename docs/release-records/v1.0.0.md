## Downloaded app and live updater

On an Apple silicon Mac running macOS 26.6.2, fresh downloads passed the release
verifier, including app/helper signatures, signing team, Hardened Runtime,
timestamps, notarization tickets, Gatekeeper, helper self-test, and a read-only
DMG mount. The DMG and ZIP contained matching app and helper binaries. Intel
metadata, receipts, checksums, and provenance were verified locally; its native
runtime and signing checks passed on the Intel runner above.

The public arm64 app was also launched with the quarantine marker from the
updater's actual download. macOS ran it from App Translocation. Opening a
synthetic archive through the app recovered the expected data through its bundled
helper. Quarantine was retained throughout the check.

The real update client passed both in CI and locally for **arm64 and x86_64**:
stable release discovery, manifest validation, installer size and SHA-256,
quarantined download, and no newer update when already on 1.0.0. The first-release
probe used 0.0.0 as the previous version; no previous public Unsit release existed.
The shipped app's version was not altered for this test.

Minimum macOS 11 CLI / macOS 12 app and Swift 5.7 runtime validation remains a
separate platform gate. See [verification limits](../verification.md).

## Corrections before first publication

Two failed candidates exposed automation issues and remained unpublished:

1. [Run 35171129178](https://github.com/ptudor/unsit/actions/runs/35171129178),
   source `dd6ed2072195ea3725dae2d8e03b2ba2d993576c`: importing the signing
   identity succeeded, but `codesign` could not use the isolated keychain.
   Commit `f2a59ef038b9d127e403fb32432d27171df1b2c7` added the keychain to
   the search list, restored the previous list during cleanup, and added a real
   signing probe. An isolated local test reproduced the failure and verified
   the correction before retrying.
2. [Run 35171989703](https://github.com/ptudor/unsit/actions/runs/35171989703),
   source `f2a59ef038b9d127e403fb32432d27171df1b2c7`: both native signed and
   notarized builds passed. Publication created an empty draft, then failed
   because GitHub's release-by-tag endpoint does not return drafts.
   Commit `5380b31b603961a8351d3bc9b0d50267e4dbcc24` switched to paginated
   draft discovery and numeric release IDs, with five new regression checks.

Before each candidate tag update, the prior workflow had stopped and no release
assets had been published. Explicit force-with-lease checks protected the two
candidate updates. The final run reused the empty draft, verified the uploaded
bytes, attested them, and published once. The published tag and assets must not
be moved or replaced.
